# Передача Boosty для Lampa другому агенту

Редакция 25.10.2026. Это инструкция для продолжения или установки на другой системе, а не разрешение изменять чужой сервер.

## Задание

Прочитай `AGENTS.md`, `README.md`, `docs/INSTALL.md` и актуальную `docs/ACCEPTANCE.md`. Сначала установи, перед тобой выпуск или предварительная версия. Если остались блокирующие исправления, не называй установку готовой; согласуй конкретный план с владельцем.

Рабочая схема: Boosty → личный сервер → Lampa → существующий плеер. Только поток по запросу, без скачивания библиотеки и перекодирования. Не устанавливай заново Lampa, TorrServer, VPN или плеер. Не меняй Home и системные службы в рамках этой задачи.

## Что входит в комплект

| Путь | Назначение |
| --- | --- |
| `server/` | API, подключение аккаунта, привязка, каталог, MP4/Range, история |
| `plugin/boosty.js` | ES5 расширение Lampa с пультом и плеером |
| `scripts/login.py` | Вход владельца на официальном сайте в отдельном браузере |
| `scripts/manage.py` | Локальное управление без вывода ключей |
| `compose.yaml`, `Dockerfile`, `.env.example` | Изолированный сервис и образ |
| `requirements*.lock/txt` | Закреплённые зависимости |
| `tests/` | Проверки серверного контракта и JavaScript |
| `docs/` | Установка, приёмка, передача, иллюстрации |

В комплект **не входят** cookies, пароли, токены, admin.json, state.sqlite3, история пользователя, APK телевизора и конфигурация исходной домашней сети. Не ищи их в старой переписке. Другой владелец должен войти в свой аккаунт самостоятельно.

## Что выяснить на новой системе

ОС/архитектура сервера, Docker/Compose, разрешённый каталог установки, постоянный LAN адрес и подсеть, реальный origin Lampa, модель/Android ТВ и используемый плеер. Если всё это видно из разрешённого read-only доступа, сначала исследуй, а не задавай владельцу список технических вопросов.

Разрешение на публикацию этого репозитория не разрешает новую установку, смену аккаунта или отключение служб. Разрешение на текущую установку не переносится между владельцами. Сначала подготовь конкретные изменения и возврат; запрос согласия должен быть последним шагом перед действием, если его ещё нет.

## Порядок продолжения

1. Проверь статус и ограничения из ACCEPTANCE. Прогони тесты последовательно по AGENTS, если меняешь код.
2. Подготовь отдельный Compose, адреса и копию данных существующей установки, если обновляешь её.
3. Следуй INSTALL: сервер → SSH/локальный admin → вход владельца → привязка → ТВ-приёмка.
4. Не доказывай закрытый доступ открытым роликом. Отдельно зафиксируй реальное продолжение во внешнем плеере.
5. После завершения выдай отчёт по шаблону INSTALL. Укажи версии и ограничения, не вставляя секреты.

## Что делать при изменении API Boosty

Не ослабляй проверку прав или SSRF-защиту ради восстановления потока. Сначала воспроизведи изменение на доступном владельцу видео; сохрани только обезличенную форму ответа. Добавь минимальный контрактный тест и исправь общую точку. Не добавляй новые форматы, обход блокировок и несколько аккаунтов без отдельной задачи.

## Контекст по телевизору

Projectivy и оптимизация телевизора — отдельная работа. Новый Home может занимать память одновременно со старым. Покупка Premium сама по себе не доказывает ускорение. Нельзя переносить готовый debloat-профиль с другого телевизора, отключать Яндекс вслепую или очищать данные нужных приложений. Сначала замеры в одинаковых условиях и обратимый эксперимент с отдельным разрешением.

## Обновление авторов и нескольких ТВ

Авторы открываются сразу, навигация представлена вкладками. Имя и аватар берутся из blog.owner, описание и обложка — из blog. Квадратная сетка авторов использует CSS aspect-ratio (Chromium/WebView 88+).

Привязки теперь добавляются, а не заменяются. На каждом устройстве один активный просмотр; запуск на другом не отзывает его. История общая: последнее полученное обновление позиции побеждает. Смена аккаунта отзывает все прежние устройства. Схема SQLite не менялась; при обновлении сохранять volume. Ранее отозванные старой версией ключи автоматически не восстанавливаются — такое устройство нужно привязать заново один раз.

По просьбе владельца новая итерация проверяется только в локальном браузере. Не подключайтесь к ТВ ради повторения проверки без нового запроса. Подробные результаты — в ACCEPTANCE.
