# Boosty для Lampa: инструкция для ассистента и владельца

Редакция: 25.10.2026. Команды рассчитаны на отдельный Linux-сервер с Docker Compose и компьютер владельца. Перед использованием проверьте [статус выпуска](ACCEPTANCE.md).

Это руководство повторяет структуру практического TV-руководства: маршрут, ограничения, этапы, проверки и возврат. Оно не требует переустановки медиастека или замены домашнего экрана телевизора. Нужен весь репозиторий/архив, одного Markdown-файла недостаточно.

## Короткий обязательный маршрут для агента

1. Прочитать `AGENTS.md`, это руководство и `HANDOFF.md`; уточнить разрешённую систему и результат.
2. Проверить ОС/архитектуру сервера, Docker Compose, свободную память, адреса и занятость портов. Не брать адреса первой установки за новые значения.
3. Подготовить отдельную папку, `.env`, перечень изменений и возврат. Получить разрешение на установку на этой системе, если его ещё нет в текущем чате.
4. Запустить только этот сервис. Проверить здоровье и недоступность административного порта из LAN.
5. Предоставить владельцу официальный сайт Boosty для входа; пароль и код он вводит сам.
6. Добавить адрес расширения в существующую Lampa, подтвердить показанный на ТВ код.
7. Проверить настоящий ТВ: карточки → качество → изображение/звук → перемотка → выход → продолжение.
8. Удалить временные файлы авторизации, закрыть свой SSH-туннель и законченные диагностические процессы. Данные рабочего сервиса сохранить.
9. Выдать короткий отчёт: что изменено, что проверено, где откат и что осталось непроверенным.

## Задание агенту

Установи серверный плагин Boosty и помоги владельцу войти в его аккаунт. На ТВ должна появиться удобная навигация по доступным видео в Lampa. Не изменяй системные службы, VPN, аккаунты других приложений и Home. История другой установки и её разрешения не заменяют согласие нового владельца.

## Критерии завершения

- Сервис работает после перезапуска контейнера, доступен с ТВ; админка не доступна соседним устройствам.
- Вход выполнен владельцем, секреты не выведены в чат или публичные файлы.
- Пульт открывает автора, карточку и выбор качества; доступны только разрешённые аккаунту видео.
- Подтверждены изображение, звук, перемотка в обе стороны и фактическое продолжение после выхода/повторного запуска.
- Если платной подписки нет, отчёт прямо говорит: платный ролик не проверен.
- Существующие приложения и их данные сохранены; описан возврат.

## Цель и ограничения

Это поток по запросу, без предварительного скачивания и перекодирования. Поддерживаются готовые MP4 Boosty; HLS/DASH-only пока не поддерживаются. Можно привязать несколько телевизоров к одному аккаунту. Каждый новый код добавляет устройство и сохраняет прежние подключения. На каждом устройстве свой просмотр, история общая: последнее обновление позиции побеждает. Сервер допускает до четырёх одновременных HTTP-потоков. При смене аккаунта все прежние привязки отзываются.

| Параметр | Что подставить |
| --- | --- |
| `SERVER_IP` | Постоянный IPv4 адрес сервера в домашней сети |
| `LAN_CIDR` | Доверенная подсеть, например `192.168.1.0/24` |
| `LAMPA_ORIGIN` | Фактическое начало адреса Lampa: схема + хост + порт, без пути и завершающего `/` |
| `SERVER_SSH` | Проверенный SSH alias или пользователь@адрес |
| `INSTALL_DIR` | Новая отдельная папка сервиса на сервере |

В командах заменяйте шаблоны, не запускайте их буквально. Примеры IP в `.env.example` вымышленные. Не используйте `*` для разрешённых origins или `0.0.0.0/0` для доверенной сети. Для Lampa, открытой по HTTPS, обычный HTTP backend может блокироваться браузером: согласуйте доверенный HTTPS маршрут отдельно, не отключайте безопасность браузера.

## 1. Проверка системы

На сервере, только чтение:

```sh
uname -m
docker version
docker compose version
free -m
df -h .
ss -lnt
```

Нужны свободные порты 19118 (LAN) и 19117 (loopback). Не останавливайте чужой сервис, чтобы освободить порт. При конфликте измените внешний порт в Compose и URL согласованно; внутренние 8080/8081 принадлежат только контейнеру. Серверу нужен исходящий HTTPS к Boosty и его CDN.

Перед тяжёлой сборкой сохраняйте свободными максимум из 4 ГиБ и 15% RAM хоста. Один тяжёлый процесс за раз. Если сервер слабее этих требований, согласуйте отдельный бюджет с владельцем; не обходите его молча. Сборку выполняйте с ограничением ресурсов через поддерживаемые настройки сборщика либо подготовьте образ на подходящей машине. Лимиты runtime в Compose не ограничивают саму сборку.

## 2. Отдельная установка

Распакуйте исходники в выбранную новую папку, перейдите в неё. Не заменяйте существующий `docker-compose.yml` медиастека. Создайте `.env` из `.env.example`, заполните **все** значения:

```dotenv
BOOSTY_LAN_IP=192.168.1.10
BOOSTY_PUBLIC_URL=http://192.168.1.10:19118
BOOSTY_ORIGINS=http://192.168.1.10:9118
BOOSTY_NETWORKS=192.168.1.0/24
```

Несколько реальных origins перечисляются через запятую. Android-приложение может открывать Lampa с иного origin, чем браузер на ПК: выясните его по конфигурации приложения или запросу, не разрешайте все адреса наугад.

После разрешения на установку:

```sh
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
curl --fail --silent http://SERVER_IP:19118/health
```

`health` проверяет работоспособность процесса, а не оплату подписки/доступность Boosty. В конфигурации: непривилегированный пользователь, read-only файловая система, отдельное состояние, лимит 1 CPU/512 МиБ, без прав Linux capabilities.

Проверьте с другого устройства: 19118 отвечает, 19117 недоступен. Не добавляйте проброс этих портов на роутере и не присоединяйте сервис к публичному туннелю. Если LAN доступ блокирует firewall, согласуйте узкое правило только для нужной подсети, не отключайте firewall целиком.

## 3. Доступ владельца к подключению

На **сервере** создайте приватную папку и скопируйте ключ в неё, не печатая его:

```sh
umask 077
mkdir -p private
docker compose cp boosty:/state/admin.json private/admin.json
chmod 600 private/admin.json
```

Через уже проверенный SSH/SCP перенесите **только этот файл** на компьютер владельца в его приватную папку. Не включайте её в репозиторий. Для удалённого сервера откройте на компьютере SSH-туннель (проверка host key остаётся включённой):

```sh
ssh -N -L 127.0.0.1:19117:127.0.0.1:19117 SERVER_SSH
```

Если этот порт занят, используйте другой локальный порт и передайте его последующим скриптам через `--admin-url http://127.0.0.1:LOCAL_PORT`. Не публикуйте админку в LAN ради удобства.

## 4. Вход в Boosty

На компьютере владельца, в папке репозитория, создайте отдельное Python окружение. Активируйте его способом своей ОС:

```sh
python -m venv .venv-login
# Linux/macOS:
. .venv-login/bin/activate
# Windows PowerShell: .\.venv-login\Scripts\Activate.ps1
python -m pip install -r requirements-login.txt
python scripts/login.py --key-file private/admin.json --browser msedge
```

Для установленного Chrome замените `msedge` на `chrome`. Для Linux без установленного подходящего браузера используйте `python -m playwright install chromium`, затем `--browser chromium`. Это скачивает отдельный браузер; сначала проверьте ресурсы. Скрипт открывает видимое отдельное окно официального сайта `boosty.to`; пароль и код владелец вводит сам. Сессия передаётся непосредственно в локальный административный адрес, временный файл cookies не создаётся. Окно закрывается после успешного подключения или по завершении попытки.

Проверка без вывода секретов:

```sh
python scripts/manage.py --key-file private/admin.json status
```

Если вход не завершился, выясните конкретную ошибку и восстановите доступ через официальный сайт. Не покупайте подписку и не меняйте аккаунт автоматически. Обход paywall не предусмотрен. Если у владельца уже есть сессия в браузере, её можно перенести штатным средством агента с его разрешения, экспортируя только Boosty cookies в приватный временный файл, импортируя через `manage.py import-session` и сразу удаляя файл. Не извлекайте чужой профиль браузера или cookies других сайтов.

## 5. Привязка Lampa

В существующей Lampa откройте настройки расширений, добавьте URL:

```text
http://SERVER_IP:19118/boosty.js
```

Перезапустите Lampa штатно. Откройте меню **Boosty → Привязать телевизор**. На экране будет шестизначный код, действующий 5 минут. На компьютере подтвердите именно его:

```sh
python scripts/manage.py --key-file private/admin.json approve 123456
```

`123456` — пример, подставьте код с экрана. Подтверждение добавляет новое устройство; ранее подключённые телевизоры сохраняют доступ. Вход Boosty и административный ключ на телевизор не переносятся. Позиция сохраняется сервером; внешний плеер получает только временный адрес видео.

## 6. Приёмка на настоящем ТВ

Сначала проверьте один открытый ролик, затем доступный владельцу закрытый. Если закрытого нет, не заявляйте его проверенным.

| Шаг | Ожидается |
| --- | --- |
| Главная, авторы, новые видео | Пульт перемещает фокус по видимым карточкам; назад возвращает в Lampa |
| Выбор качества | Показаны реально доступные MP4 варианты |
| Просмотр 5–10 минут | Изображение и звук без постоянной буферизации |
| Перемотка +5 мин, −2 мин | Плеер корректно продолжает; сервер отвечает Range, не скачивает архив |
| Выход и повторный запуск | «Продолжить» соответствует фактическому месту, включая перемотку назад |
| Перезапуск сервиса | Авторизация и история сохранены; уже открытый поток нужно запустить заново |
| Обычная работа ТВ | VPN, SmartTube, Lampa/TorrServer/плеер, VK Видео и Home работают как прежде |

Если ViMu/другой внешний плеер не возвращает позицию, укажите это ограничение и исследуйте фактический callback. Не меняйте глобальный плеер Lampa без согласия владельца. Длинный просмотр и выход из сна — отдельные проверки; не заменяйте их кратким HTTP-запросом.

## 7. Типовые проблемы

| Что видно | Что проверить |
| --- | --- |
| Нет меню Boosty | URL скрипта, ответ 200, перезапуск Lampa, ошибки JavaScript |
| Сервер недоступен | Адрес сервера, health, firewall, фактический origin Lampa, mixed content |
| Нужно подключить аккаунт | Повторный вход владельца; файл сессии не публиковать |
| Код истёк | Получить новый код; старый не использовать |
| Нет доступа к видео | Этот же ролик на официальном сайте под тем же аккаунтом |
| Нет MP4 | Формат не поддержан первой версией; не обещать HLS/DASH |
| Ссылка истекла/источник изменился | Выйти из плеера и открыть ролик заново |
| Позиция не сохранена | Сообщение ошибки в Lampa, работа сервера, callback внешнего плеера |

Журналы проверяйте точечно. Временные адреса потоков тоже не публикуйте. При отладке не включайте дамп Authorization/cookies или полных upstream URL.

## 8. Обновление, сохранность и возврат

Перед обновлением сохраните точную версию исходников/образа. Для согласованной копии состояния остановите **только boosty**, скопируйте `/state` в приватную резервную папку и снова запустите его. Копия содержит доступ к аккаунту и историю; храните её как секрет. Не переносите её другому владельцу.

```sh
docker compose stop boosty
docker compose cp boosty:/state private/state-backup
docker compose start boosty
```

Имя резервной папки делайте новым для каждой копии. Не перезаписывайте последнюю рабочую копию. При обычном обновлении `docker compose up -d --build` сохраняет named volume. `docker compose down -v` **удаляет данные** — не используйте его для обновления/отката.

Быстрый возврат: отключите только расширение Boosty в Lampa, выполните `docker compose stop boosty` в папке этого проекта. Остальной медиастек продолжает работать. Для отката версии верните прежние исходники/образ; перед восстановлением состояния остановите сервис и убедитесь в правильности целевого volume. Не заменяйте состояние работающего контейнера.
