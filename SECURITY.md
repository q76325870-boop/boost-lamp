# Безопасность

Этот сервис предназначен для одного владельца в доверенной домашней сети. Внешняя публикация через роутер, публичный reverse proxy или туннель не входит в поддерживаемую конфигурацию.

## Данные и доступ

- Сессия Boosty и ключ управления хранятся только в состоянии сервера. Это чувствительные данные: доступ к volume/резервной копии даёт доступ к аккаунту в рамках сессии.
- Административный порт Compose опубликован на loopback. Для удалённого управления используется SSH-туннель и отдельный ключ в заголовке.
- ТВ получает отдельный токен привязки; плеер — временный адрес конкретного просмотра. Эти адреса также не следует публиковать.
- Код проверяет право просмотра перед выдачей источника, ограничивает upstream-домены, проверяет DNS/IP и перенаправления, передаёт поток ограниченными блоками.
- HTTP внутри доверенной LAN не шифрует трафик. Гостевая или чужая сеть не считается доверенной; для неё необходима отдельная схема защищённого доступа.

## Что не отправлять в issue

`.env`, `/state`, `admin.json`, cookies/storageState, Authorization, ссылки с подписями CDN, полные журналы браузера/плеера. Достаточно кода ошибки, версии, шага воспроизведения и обезличенной формы ответа.

## Сообщение об уязвимости

Используйте приватный канал **Security → Report a vulnerability**, если он включён в репозитории. Если его нет, создайте issue только с просьбой предоставить приватный канал, без эксплуатационных деталей или секретов. Не публикуйте реальные ключи даже для демонстрации проблемы.

Предварительная версия проходит проверку; отсутствие опубликованных уязвимостей не является аудитом или гарантией безопасности.
